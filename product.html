从问题到可用流程

面向产品经理、AI 产品与数字化岗位，先看问题如何被拆解成用户场景、智能化角度、功能、反馈和验证边界。下文的用户场景是功能设计面向的任务，并非已验证的用户增长或商业效果。

推荐顺序：WebGIS → ProjectGame → ProjectGame2 → CWC。地图应用提供直接的使用流程；两个游戏原型展示复杂交互和规则设计；CWC 展示科研数据产品的生产与 QA。
01 / WEBGIS

让地点发现和行程预览在一张地图上完成

Smart Tourism WebGIS · 个人主导的本地工程原型

完整项目 →
背景问题
名称搜索、当前位置附近检索和多站路线是不同任务；自然语言输入还可能产生不存在的地点。
用户场景
用户可从地图与列表定位已收录 POI，按空间范围筛选，并对所选地点查看路线预览；这是界面提供的使用路径，未做真实用户效果评估。
功能与交互
关键字/类别/bbox/附近查询、地图点位与详情、直线预览、可选自然语言意图和道路路线；路线修改需确认。
智能化角度
可选模型只解析受限意图，POI 仍由 PostGIS 取回；失败时使用规则回退。
系统方案
Vue 与 MapLibre 负责交互，FastAPI/PostGIS 保证候选地点来自数据库；DeepSeek 仅解析受限意图，Valhalla 提供道路几何与估算时间。
结果与限制
完成基于 40 条 CSV 演示 POI 的本地原型及既有界面记录；未上线，也没有用户数、导航精度或推荐效果指标。
02 / PROJECTGAME

把战术规则变成玩家可见的决策

王国战记 · 个人独立开发的 Godot 战棋原型

完整项目 →
背景问题
单位移动、地形、敌方控制区和伤害修正需在同一张六边形战场上保持一致，并让玩家知道回合目标与行动后果。
用户场景
玩家可直接选择单位、移动和攻击，并查看关卡目标、伤害预览、城市与将领信息；尚无玩家研究或体验指标。
功能与交互
章节/关卡入口、回合推进、战斗预览、资源栏、城市/行省/将领面板与剧情卷轴。
智能化角度
敌方行动与战术反馈由代码规则驱动，不属于机器学习模型。
系统方案
轴向六边形坐标连接点击与战术规则；地图、关卡和 scenario JSON 提供数据，专门脚本处理战斗、迷雾与目标结算。
结果与限制
资料可确认第一章三个正式关卡配置及相关战斗和管理系统；当前开发工作树的新增路径尚未做全面重新验收。
03 / PROJECTGAME2

让一次造地操作产生持续可观察的世界反馈

ProjectGame2 · 个人独立设计、开发、测试与内容制作

完整项目 →
背景问题
地块放置要有选择与规划空间，同时非法操作不能损坏世界；长期模拟又需要清晰的状态和可重放验证。
用户场景
玩家从队列前三张地块卡中选择并放置，观察聚落和国家依规则发展；这一设计价值未经过玩家留存或商业数据检验。
功能与交互
18 张队列卡、重排与丢弃、合法放置、速度控制、地图覆盖层和信息面板；玩家创造世界，不直接指挥军队。
智能化角度
聚落与国家依世界状态和规则推进；自主模拟不是 LLM 智能体。
系统方案
六边形几何、权威世界状态、分阶段 tick、服务化模拟和隔离随机流；政治分离与内战为代码规则，并非 LLM 智能体。
结果与限制
V1.2 在 QA 报告指定范围为 ACCEPTED；54 项专项检查 0 失败。分离/内战 GUI 证据来自受控场景，600 tick 自然模拟未触发。
04 / CWC

把遥感研究流程整理为可核对的逐日产品

CWC · 个人主导科研项目

完整项目 →
背景问题
实地水分信息稀疏，标签、遥感变量和空间支持不同，批量生产必须区分模型表现与产品完整性。
用户场景
研究工作形成可按日期追踪的叶片相关冠层含水量产品清单；未证明其已公开发布或被外部用户采用。
功能与交互
标签来源记录、特征融合、模型选择、逐日推理、合格结果复用和最终 QA。
智能化角度
LightGBM 负责 CWC 回归，逐日生产与 QA 是独立的数据工程环节。
系统方案
M7 LightGBM 接收 20 个输入特征；生产流程按日期组织全球 0.1° 栅格，并校验日文件和月度配对。
结果与限制
最终记录 6,789 张逐日文件、223 组月度配对，QA 为 PASS，仍保留 14 条 WARN；这些是产品完整性结果，不等同于独立地面精度。
补充项目：LFMC 展示多源遥感样本、功能型多头模型与云南单旬区域产品；其全球正式生产尚未启动。

WebGIS · Local Prototype

Smart Tourism WebGIS

以南京景点 POI 为例，把地图检索、米制附近查询、受限自然语言意图和道路路线预览接入同一个本地原型。

项目简介

项目围绕 40 条 CSV 演示 POI 构建本地旅游 WebGIS。前端用 Vue 和 MapLibre 展示地图、景点与路线；后端通过 FastAPI 和 PostGIS 处理地点检索；可选 DeepSeek 用于受限意图解析，Valhalla 用于道路路线。它不是上线的旅游平台、实时导航或大规模推荐系统。

背景问题

地图上“找到地点”涉及多个不同问题：名称/类别检索、当前视野筛选、真实米制附近查询，以及对多个地点的行程预览。自然语言输入还可能产生不存在的景点；直线顺序预览也不能冒充道路距离。项目将这些需求拆成明确的查询与反馈环节。

解决方案

把 POI 身份和坐标保留在 PostGIS，以参数化查询返回 GeoJSON。地图显示位置、列表、热力和路线；用户可检索、筛选、收藏并选定地点。自然语言路径仅将输入转成受限条件或偏好，实际候选仍来自数据库；模型不可用时有本地规则回退。用户选择的点可分别查看直线预览或 Valhalla 的道路路线与估算时间。

技术架构

前端 App.vue 管理 MapLibre source/layer、查询状态及路线展示；Axios 调用 FastAPI。后端处理普通检索、bbox、geography 米制附近查询、旅游卡片和行程路由。PostGIS 的 places 表以 EPSG:4326 存储点位；路网服务通过 Valhalla 取得几何、道路距离和估算时间。DeepSeek 是按密钥启用的可选外部 API，仅参与意图和行程条件处理，不是训练出的项目专属模型。

项目区分直线顺序预览与道路路线；对缺失旅游元数据、外部服务失败和路线修改待确认等状态提供显式反馈。后端和前端目前面向本地地址，没有线上部署或服务等级证据。

核心功能

  • POI 名称、类别、地图范围与附近米制查询；地图点图层和热力图。
  • 地点详情、当前浏览器本地收藏、手动选点与直线顺序预览。
  • 可选的 DeepSeek 受限意图处理与 PostGIS 真实候选检索。
  • Valhalla 的步行、骑行、驾车道路路线与时间估算；对话式修改先预览再确认。

AI / 智能化能力体现

项目接入可选 DeepSeek API，将自然语言需求解析成受限查询条件或行程偏好；实际地点候选仍由 PostGIS 中的 POI 决定，模型不能凭空新增地点。外部 API 不可用时有本地规则回退。道路路线由 Valhalla 计算；本项目没有训练专属大模型或证明推荐效果。

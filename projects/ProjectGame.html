项目简介

这是 Godot 4.6/GDScript 的六边形回合制战棋原型。玩家从章节入口进入地图，查看目标，在战场直接对单位下达移动和攻击指令，并通过城市、行省、将领和资源面板处理局部决策。可核实的正式战役内容为第一章三个关卡配置；项目不是已上线的商业游戏。

背景问题

战棋原型需要让地块、单位、关卡目标和 UI 使用同一套规则身份。移动不仅是几何距离，还受地形、桥/渡口、敌方控制区、占位和剧情限制影响；战斗则需要把伤害与修正项解释给玩家。更多城市和章节规则加入后，状态协调和保存边界也变得重要。

解决方案

用轴向坐标 q/r 标记六边形地块并连接点击、邻居、距离与范围；以关卡 JSON 组织地图、目标和事件，由战斗规则模块处理移动成本和伤害。HUD 提示回合、资源、目标与伤害预览，城市/省份/将领面板承接不同层级的操作。进度和活动战斗快照分开存储，以限制调试状态污染正式进度。

技术架构

StartMenu.tscn 进入章节与地图流程；战斗宿主运行时建立视口、地图、相机和 HUD。HexMath.gd 负责坐标，HexGrid.gd 协调地图、回合、单位、城市和 UI 状态；CombatResolver.gd、CombatModifierCollector.gd、BattleScenarioDirector.gd、FogOfWarController.gd 承担专门规则。stages.json、地图与 scenario JSON 为第一章关卡提供数据。

HexGrid.gd 职责集中是已知维护风险。当前分支的 Native3D 表现只在第一章首关的特定 campaign 条件路径启用；不能说所有关卡都已完成相同 3D 表现。

核心功能

  • 六边形地图、单位选择、按地形和控制区计算的移动范围。
  • 攻击/反击与伤害预览，玩家、可选盟方和敌方的回合阶段。
  • 城市、行省、建筑、资源、生产和将领面板。
  • 第一章三个正式关卡配置、剧情卷轴与关卡进度记录。
  • 可见/已探索地块及视线相关的战争迷雾规则。

AI / 智能化能力体现

战棋中的敌方行动由游戏规则与脚本驱动；六边形坐标、移动范围、敌方控制区、伤害修正与回合状态构成可解释的交互规则。这里的 AI 指规则型对手行为，不是机器学习模型或大语言模型。
